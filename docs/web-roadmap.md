# Web 端里程碑计划

> 状态：2026-11 制定。Web 端（PWA）先行，界面与交互以 [界面与交互设计](design/ui-interaction.md) 和 Figma 设计稿为准。
> 每个阶段拆成若干个小 PR，各自可独立合并、可在线预览（GitHub Pages）。桌面端（Tauri）复用同一套前端，随 Web 端一起推进。

## 总体原则

- **小步合并**：每个 PR 只做一件事，CI（lint / test / build）通过即可合并，主干始终可用。
- **本地优先**：所有阶段数据都只存 IndexedDB；数据库升级用 Dexie 版本迁移，旧数据不丢。
- **逻辑与界面分离**：解析、去重、统计等纯逻辑放在 `src/lib`（不依赖 DOM），带单元测试，将来可抽到 `packages/core` 给小程序和 API 复用。
- **响应式一套代码**：`< 768` 移动布局（底部 Tab），`768–1279` 侧边栏折叠为图标栏，`≥ 1280` 完整桌面布局。

| 阶段 | 目标 | 主要内容 | 对应设计 |
| --- | --- | --- | --- |
| W1 设计系统与布局 | 换上设计稿的视觉和导航骨架 | 颜色 / 字体 / 间距 / 圆角 Token（浅色 + 深色）；Button、Badge、IconButton、Dialog 等基础组件；侧边栏 + 底部 Tab 的响应式外壳；Hash 路由与各一级页面占位；现有明细功能迁入新外壳；「记一笔」弹窗与快捷键 N | 00 设计规范、M01、D01 外壳 |
| W2 明细与记一笔 | 记账体验达到设计稿 | 数据模型 v2（商户、标签、来源、转账）；明细按日分组 + 桌面表格；搜索与筛选条；流水详情面板编辑；删除后 5 秒撤销；记一笔：金额键盘（四则运算）、分类宫格（按频次）、沿用上次、再记、转账模式 | M01、M02、D01 |
| W3 分类、账户与预算 | 账本基础数据可管理 | 分类管理（图标、颜色、排序、增删改）；账户管理（类型、初始余额、余额计算）；月度预算（总预算 + 分类预算），明细汇总卡显示预算进度（> 80% 橙、> 100% 红）；「我的」页 | M06、D01 KPI |
| W4 导入中心 | 账单导入不丢不重 | 统一导入管线（嗅探 → 解析 → 去重 → 自动分类 → 预览确认 → 入账）；导入批次与整批撤销；通用 CSV 字段映射与模板；微信账单（xlsx / csv）、支付宝账单（GBK csv）内置模板；自动分类规则；JSON 备份恢复 | M04、M05、D03 |
| W5 统计分析 | 看得懂的分析 | 周 / 月 / 年 / 自定义区间；KPI 与上期对比；收支趋势柱状图、支出构成环形图、商户 Top、预算执行；所有图表下钻到带筛选的明细；图表数据表视图（无障碍） | M03、D02 |
| W6 设置与数据 | 数据属于你 | 导出 CSV / JSON；外观（浅色 / 深色 / 跟随系统、收支配色切换）；许可与授权页；PWA 更新提示；（可选）WebAuthn 隐私锁 | M06 |

开放接口页（D04）依赖自托管同步服务 `apps/api`，截图 OCR 依赖识别方案选型，这两项不在 Web 端首轮范围内，等服务端方案确定后再排期。
